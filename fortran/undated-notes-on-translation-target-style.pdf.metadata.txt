SUBROUTINE MATMUL(X,Y,IDIM)
      REAL X(1), Y(1), Z(100)
      INTEGER IDIM
      DO 100 I = 1, IDIM, 1
         Z(I) = 0
         DO 200 J = 1, IDIM, 1
  200       Z(I) = Z(I) + X(I,J) * Y(J,I)
         DO 100 J = 1, IDIM, 1
  100       X(I) = Z(I)
      RETURN
      END

The important part in the scan is just to note that the reason this
is a translator, not a compiler, is partly that I really didn't want
to do the hard work of compilation when there were already tools to
do that, but also I wanted from an aesthetic point of view to design
a target language that allowed one to see what the Fortran had been
doing, and even to intersperse Lisp code later into the translation.

Considerable effort was made to preserve Fortran semantics for
Fortran-declared parts while allowing Lisp semantics for other parts.
This is essential because of the call-by-reference nature of Fortran,
which still had to mesh with interspersed Lisp that might not presume
such semantics. So, for example, FORTRAN-declared variables were
replaced differently than Lisp variables, becoming FPUT or FGET
statements in the fully expanded code. Similarly, calls to functions
had to be managed differently though that isn't shown here.
(It is mentioned in the documentation.)
